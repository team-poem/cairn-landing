# 첫 협업 실험

목표는 케언 랜딩을 함께 개선하면서 서로의 작업 선언과 변경을 에이전트가 읽는지 확인하는 것입니다.

## 시작 조건

1. 공통 기반 PR을 팀원 1명이 리뷰하고 squash 머지합니다. 승인 없이 관리자도 머지하지 않습니다.
2. 참여자는 각자 별도 클론에서 세션을 엽니다. 한 로컬 폴더를 여러 사람이 공유하지 않습니다.
3. 각자의 핸들로 onboard하고 최신 main에서 start-work를 실행합니다.

## 나눌 작업

아래는 배정 후보이며 아직 아무도 담당하지 않습니다. 각자 하나를 선택해 claim을 push합니다.

| 작업 | 주 파일 | 완료 기준 |
| --- | --- | --- |
| 히어로 메시지와 톤 다듬기 | `components/landing/Hero.tsx` | 엔진의 대상 사용자와 가치가 첫 화면에서 읽힌다 |
| 실행 흐름과 근거 보강 | `components/landing/Workflow.tsx` | 실제 엔진 동작과 예제의 구분이 명확하다 |
| 기능 소개와 시작 안내 개선 | `components/landing/Features.tsx`, `components/landing/GetStarted.tsx` | 공식 문서와 예제로 자연스럽게 이어진다 |

공통 파일 `app/page.tsx`, `app/globals.css`, `lib/cairn.ts` 변경이 필요하면 claim의 next에 미리 씁니다. 새 섹션 스타일은 섹션별 CSS Module을 추가하면 충돌을 줄일 수 있습니다. 의존성·레이아웃·공통 CSS는 작은 선행 PR로 합의합니다.

## 검증할 장면

- 두 사람이 claim을 push한 뒤 상대 digest에 목표가 보인다.
- 별도 테스트 브랜치에서 공통 CSS를 한 사람이 수정하고 pulse한다. 다른 사람의 `guard app/globals.css`가 편집 중임을 알려 차단하는지 확인한다. 둘 다 동시에 쓰지는 않는다.
- 첫 사람이 커밋한 뒤 두 번째 사람은 pulse하고, 편집 중 차단이 미머지 변경 알림으로 바뀌는지 확인한다.
- 먼저 머지된 PR 뒤, 다른 사람은 깨끗한 작업 트리에서 pulse하여 main을 따라잡는다.
- 각자 handoff 저널을 남기고, 다음 세션에서 해당 이벤트가 읽히는지 확인한다.

아직 두 사람이 참여한 실전 검증은 수행하지 않았습니다. CI의 다중 클론 모의 테스트와 구분합니다.

## 이번 초기화에서 발견한 것

템플릿 생성 직후 CI가 이전 템플릿 개발 claim을 prune했습니다. 그 사이 만든 작업 브랜치가 main을 merge하면 타 브랜치 claim 삭제 금지 훅이 막았고, pulse는 이를 파일명이 비어 있는 충돌로 안내했습니다.
훅을 우회하지 않고 prune이 끝난 최신 main에서 작업 브랜치를 다시 만들어 진행했습니다. 템플릿 측 개선 후보: 봇 정리 변경을 main에서 받아올 때의 guard 판정과 실패 이유 표시. 이 저장소에서는 하네스 본체를 수정하지 않았습니다.

온보딩 테스트가 실제 앱의 이미 초기화된 AGENTS.md를 복사하면서 setup 검사 2개가 실패했습니다. 테스트 임시 저장소에 미초기화 AGENTS.md를 명시적으로 생성하도록 fixture만 보정했습니다.

## 의존성 검토

공식 Sites 0.3.0 스타터의 고정 버전 설치에서 npm audit 11건(높음 8, 중간 2, 낮음 1)이 보고됐습니다. 이번 배포는 `dist/client` 정적 파일만 제공하며 Node/RSC/Worker 서버는 배포하지 않습니다. 의존성을 사용하는 개발·빌드 환경의 경고까지 해소된 것은 아닙니다. 후속 의존성 PR에서 vinext·React RSC·Vite·Cloudflare 계열을 함께 검증해 업데이트해야 합니다. `audit fix --force`는 실행하지 않았습니다.
